1. ESTRUCTURA GENERAL DE NAVEGACIÓN
--------------------------------------------------------------------------------

Sidebar fija con 3 secciones principales:

  [1] ATRIBUTOS
  [2] CATEGORÍAS
  [3] PRODUCTOS

Cada sección abre su propio módulo de gestión con vista de tabla/lista y
acciones CRUD.

El orden importa: primero se crean Atributos, luego Categorías (que usan
Atributos), y finalmente Productos (que usan Categorías y Atributos).
Esto debería estar visualmente sugerido, por ejemplo con un breadcrumb o
un texto de onboarding que diga "Empezá por aquí →".


--------------------------------------------------------------------------------
2. MÓDULO: ATRIBUTOS
--------------------------------------------------------------------------------

LISTA DE ATRIBUTOS
  - Tabla con columnas: Nombre | Key | Tipo | ¿Es estático? | Valores Enum
  - Filtros: por tipo (text, number, boolean, enum), por is_static
  - Botón: [+ Nuevo Atributo]

  Indicadores de tipo:
    text    → badge azul  "Texto"
    number  → badge verde "Número"
    boolean → badge naranja "Booleano" (dinámico, solo para variantes)
    enum    → badge violeta "Enum"

  Columna "¿Es estático?":
    Sí → se usa a nivel producto (info del producto)
    No → se usa a nivel variante (opción de variante)

  NOTA IMPORTANTE: los atributos boolean siempre son dinámicos (variantes).
  Los de tipo text y number siempre son estáticos (info del producto).
  Los enum pueden ser cualquiera de los dos.

FORMULARIO: CREAR / EDITAR ATRIBUTO
  Campos:
    - Nombre*
    - Key* (slug único, no editable una vez creado para evitar inconsistencias)
    - Tipo de dato* (selector: text | number | boolean | enum)
    - ¿Es estático? (toggle, solo habilitado si tipo = enum)
      → Si tipo = text o number: se fuerza is_static = true
      → Si tipo = boolean: se fuerza is_static = false
      → Si tipo = enum: el usuario elige

  Sección condicional (solo si tipo = enum):
    Valores posibles (chip input):
      [ valor1 ] [ valor2 ] [ + Agregar valor ]

  ADVERTENCIA al editar:
    Si el atributo ya está asignado a categorías o productos, mostrar:
    "⚠ Este atributo está en uso. Cambiar su tipo o valores puede afectar
     productos y variantes existentes."

  Botones: [Cancelar] [Guardar]


--------------------------------------------------------------------------------
3. MÓDULO: CATEGORÍAS
--------------------------------------------------------------------------------

LISTA DE CATEGORÍAS
  - Tabla con columnas: Nombre | Cantidad de Atributos | Cantidad de Productos
  - Botón: [+ Nueva Categoría]
  - Click en una fila abre el detalle de la categoría

DETALLE / EDICIÓN DE CATEGORÍA
  Layout dos columnas:
    Izquierda: Info básica
      - Nombre* (editable)

    Derecha: Atributos de la categoría
      Lista de atributos asignados:
        [ Key ] [ Nombre ] [ Tipo ] [ Estático ] [ X quitar ]

      Buscador para agregar atributos existentes:
        [ Buscar atributo... ] → dropdown con atributos disponibles → [Agregar]

  FLUJOS CRÍTICOS al modificar atributos de categoría:

  Al AGREGAR un atributo a una categoría que ya tiene productos:
    Modal de confirmación:
    "Esta categoría tiene N producto(s). Al agregar este atributo:
     - Si es estático: deberás completar el valor en cada producto.
     - Si es dinámico: deberás completar el valor en cada variante de cada producto.
     ¿Querés continuar? [Cancelar] [Sí, agregar y gestionar después]"

  Al QUITAR un atributo de una categoría que ya tiene productos:
    Modal de confirmación:
    "⚠ ACCIÓN DESTRUCTIVA
     Esta categoría tiene N producto(s). Al quitar este atributo:
     - Se eliminarán todas las implementaciones de este atributo en productos
       y variantes asociadas.
     Esta acción no se puede deshacer.
     ¿Querés continuar? [Cancelar] [Sí, quitar y eliminar implementaciones]"

  Botones: [Cancelar] [Guardar Categoría]


--------------------------------------------------------------------------------
4. MÓDULO: PRODUCTOS
--------------------------------------------------------------------------------

LISTA DE PRODUCTOS
  - Tabla con columnas: Código | Título | Precio | Marca | Categoría | Variantes
  - Filtros: por categoría, por marca
  - Búsqueda por código o título
  - Botón: [+ Nuevo Producto]

FORMULARIO: CREAR / EDITAR PRODUCTO
  El producto es la entidad más compleja. Se divide en pasos o secciones:

  ─── SECCIÓN 1: INFO BÁSICA ──────────────────────────────────────────────────
    - Código*
    - Título*
    - Precio*
    - Marca
    - Descripción (textarea)
    - Categoría* (selector)
      → Al seleccionar categoría: se muestran automáticamente los atributos
        heredados de esa categoría en la sección de atributos.

  ─── SECCIÓN 2: ATRIBUTOS ────────────────────────────────────────────────────
    Subsección 2A: Atributos heredados de la categoría (solo lectura en la lista,
    pero con campo para implementar el valor)
      Tabla:
        [ Nombre ] [ Tipo ] [ Estático ] [ Valor actual ]
        → Los estáticos: mostrar input/select para cargar el valor
        → Los dinámicos: se gestionan en la sección de variantes

    Subsección 2B: Atributos propios del producto
      Lista de atributos adicionales (no de la categoría):
        [ Key ] [ Nombre ] [ Tipo ] [ Estático ] [ X quitar ]

      Buscador para agregar atributos:
        Solo permite atributos que no estén ya en la categoría ni en el producto.
        [ Buscar atributo... ] → [Agregar]

    FLUJO CRÍTICO al quitar un atributo propio del producto:
      Modal:
      "⚠ Al quitar este atributo del producto se eliminarán sus implementaciones
       en todas las variantes. ¿Continuar? [Cancelar] [Sí, quitar]"

  ─── SECCIÓN 3: IMPLEMENTACIONES ESTÁTICAS ───────────────────────────────────
    (Se puede integrar en la sección 2A, o ser una sección separada)
    Lista de todos los atributos estáticos del producto (categoría + propios)
    con su valor asignado.

    Para cada atributo estático:
      - text:    input de texto
      - number:  input numérico
      - enum (is_static=true): selector con los enum_values del atributo

    Estado de completitud: indicador visual si falta implementar alguno.
    "2 de 5 atributos completados"

  ─── SECCIÓN 4: VARIANTES ────────────────────────────────────────────────────
    Muestra los atributos dinámicos (is_static = false) que aplican al producto
    (categoría + propios).

    Si no hay atributos dinámicos: mensaje "Este producto no tiene atributos
    dinámicos. No necesita variantes."

    Si hay atributos dinámicos:
      Lista de variantes existentes en formato tabla:
        [ ID/# ] [ atributo1 ] [ atributo2 ] ... [ Acciones ]
        Cada celda muestra el valor del atributo en esa variante.

      Botón: [+ Agregar Variante]

      Al agregar variante: formulario inline o modal con:
        Para cada atributo dinámico del producto:
          - boolean: toggle/checkbox
          - enum (is_static=false): selector con enum_values
        Botón: [Confirmar Variante]

      NOTA: No se permiten variantes duplicadas (misma combinación de valores).

      TODO (pendiente de implementar): editar variante existente.
      Por ahora solo crear y eliminar.

  Botones de acción del producto: [Cancelar] [Guardar Producto]


--------------------------------------------------------------------------------
5. FLUJOS ESPECIALES Y ADVERTENCIAS CRÍTICAS
--------------------------------------------------------------------------------

El todo.txt del repo marca que el diseño de categorías y atributos es CRÍTICO.
El dashboard debe reflejar esto con:

  5A. Panel de impacto antes de guardar cambios de categoría
    Al modificar atributos de una categoría → mostrar cuántos productos
    y variantes se verán afectados ANTES de confirmar.

  5B. Log de cambios (opcional, mejora futura)
    Historial de cambios en atributos de categoría/producto para auditoría.

  5C. Indicador de "pendiente de implementar"
    Si un producto heredó un nuevo atributo de la categoría pero aún no
    tiene implementación, mostrar badge "⚠ Incompleto" en la lista de
    productos. El listado de productos debería permitir filtrar por este
    estado.

  5D. Bloqueo de borrado de atributos en uso
    Si un atributo está asignado a una categoría o producto, no se puede
    eliminar directamente. Mostrar:
    "No podés eliminar este atributo porque está en uso en:
     - Categorías: [lista]
     - Productos: [lista]
     Quitalo de esas entidades primero."


--------------------------------------------------------------------------------
6. COMPONENTES UI REUTILIZABLES SUGERIDOS
--------------------------------------------------------------------------------

  - AttributeTypeBadge: badge de color por tipo de atributo
  - AttributeValueInput: input inteligente según tipo (text/number/bool/enum)
  - VariantTable: tabla de variantes con atributos como columnas
  - ConfirmDestructiveModal: modal estándar para acciones con impacto cascada
  - ImpactSummary: bloque que muestra "N productos y M variantes afectados"
  - CompletenessIndicator: barra o texto de "X de Y atributos implementados"


--------------------------------------------------------------------------------
7. ORDEN RECOMENDADO DE IMPLEMENTACIÓN DEL FRONT
--------------------------------------------------------------------------------

  Fase 1: ABM básico de Atributos (sin relaciones)
  Fase 2: ABM de Categorías + asignación de atributos (sin warnings aún)
  Fase 3: ABM básico de Productos (info básica + categoría)
  Fase 4: Implementaciones estáticas en Producto
  Fase 5: Variantes (crear + listar)
  Fase 6: Warnings y flujos críticos al modificar categorías/productos con datos
  Fase 7: Modificar variantes existentes (pendiente en backend también)
  Fase 8: Indicadores de completitud + filtros avanzados
