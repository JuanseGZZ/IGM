DESCRIPCION GENERAL
-------------------
Interfaz frontend de la plataforma SaaS "TuEcom", orientada al cliente final.
Permite crear y gestionar tiendas online por suscripcion.
Stack: HTML5 + Bootstrap 5 + JavaScript Vanilla
Persistencia: localStorage (sin backend conectado, datos de prueba)
Autenticacion: guard client-side via auth.js

1. auth.js
--------------------------------------------------------------------------------
Tipo:       JavaScript utilitario
Tamano:     ~2 KB

Descripcion:
  Modulo de autenticacion client-side. Protege paginas privadas y gestiona
  el estado de sesion mediante localStorage.

Funciones exportadas:
  isLogged()
    Devuelve true/false segun si existe la clave "logged" en localStorage.

  redirectToIndex()
    Redirige el navegador a index.html.

  ensureLogoutInNav()
    Inserta o muestra el item "Cerrar sesion" en el navbar si el usuario
    esta logueado. Si no esta logueado, lo oculta.

  guardPrivatePages()
    Verifica autenticacion al cargar la pagina. Si el usuario no esta
    logueado y la pagina actual no es index.html, redirige a index.html.

Evento:
  Se ejecuta completo en DOMContentLoaded.

Notas:
  - La autenticacion es exclusivamente client-side (sin validacion backend).
  - La clave "logged" en localStorage se establece en index.html al hacer login.
  - No hay tokens JWT ni sesiones seguras; es un prototipo UI.

  Enterprise: Custom  | 600+ productos, emails ilimitados, analitica con IA

================================================================================
CONSIDERACIONES DE SEGURIDAD
================================================================================

ADVERTENCIAS IMPORTANTES (para cuando se implemente backend):

1. AUTENTICACION CLIENT-SIDE INSEGURA
   Actualmente el estado de sesion se guarda en localStorage["logged"].
   Cualquier usuario puede modificar este valor desde la consola del navegador
   y saltear el guard. Implementar autenticacion con JWT o sesiones de servidor.

2. CONTRASENAS EN TEXTO PLANO
   El formulario de registro guarda el objeto usuario (incluyendo contrasena)
   directamente en localStorage. Nunca almacenar contrasenas en texto plano.
   Usar hashing en el servidor (bcrypt, argon2, etc).

3. VALIDACION SOLO EN CLIENTE
   Todos los formularios solo tienen validacion de UI. Siempre validar y
   sanitizar los datos en el servidor.

4. CREDENCIALES EXPUESTAS
   Los datos del usuario pueden leerse facilmente desde DevTools > Application
   > localStorage. No almacenar datos sensibles en localStorage en produccion.


================================================================================
PATRONES DE DISENO UTILIZADOS
================================================================================

Modal Pattern:
  Modal de Bootstrap para login/registro en index.html.
  Evita redireccion a pagina separada de auth.

Tab Pattern:
  Bootstrap nav-tabs en dshb.manage.html para separar
  Productos / Pedidos / Estadisticas / Campanas.

Accordion Pattern:
  Bootstrap accordion en la lista de pedidos para
  mostrar/ocultar el detalle de cada orden.

Guard Pattern:
  auth.js actua como middleware de ruta: si no hay sesion
  y la pagina no es index.html, redirige al landing.

Card Pattern:
  Uso consistente de Bootstrap cards para mostrar
  tiendas, KPIs, transacciones y planes de precios.

Countdown Redirect Pattern:
  dshb.payment.success.html y failure.html usan setInterval
  para redirigir con contador visible al usuario.
